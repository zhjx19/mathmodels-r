# 案例 05 · 系统评价：耦合协调度 + 障碍度

> 三子系统熵权得分 → 归一化 → 子系统权重 → 耦合协调度（标准式 vs 修正式）→ 障碍度

## 这个案例解决什么

"多系统协调发展"类题目的标准答案模板：把"科技—经济—生态"三个子系统各自的
综合得分算出来，再算**耦合协调度**衡量协调发展水平，最后用**障碍度模型**
找出每个地区每个年份的瓶颈子系统。特别地，本案例把**标准式与修正式**耦合度
放在一起对比，**用数据说明**文献指出的"传统 C 值区分度差"这一缺陷。

## 用户大概会这么问

- "耦合协调度怎么算？公式里的 C、T、D 分别是什么？"
- "耦合度和耦合协调度有什么区别？"
- "标准式和修正式耦合度该用哪个？"
- "障碍度模型怎么做？怎么找瓶颈？"
- "多个子系统的权重怎么定？"

## 数据

`../data/cdev-sim.csv`：8 个地区 × 10 年（2015–2024）× 3 个子系统
（科技创新 3 指标 / 经济发展 3 指标 / 生态环境 3 指标）。

## 覆盖的包函数

`weight_entropy` · `rescale` · `coupling_degree` · `obstacle_degree`

## 流程

1. 三个子系统各自 `weight_entropy()` 做熵权综合评价（注意单位 GDP 能耗是**负向**指标）；
2. 子系统得分 `rescale()` 归一化到 [0,1]，再定子系统权重（熵权）；
3. `coupling_degree()` 按年份分组批量算**标准式**与**修正式**；
4. 按协调度给 10 级协调等级，看等级分布与末年各地区等级；
5. `obstacle_degree()` 算二级指标障碍度，再 `summarise(across(...), .by=)` 汇总一级。

## 关键决策点

- **耦合协调度要求子系统得分在 [0,1]**，所以必须先 `rescale`；
- **归一化过的列在 `weight_entropy` 里要标 `index = NA`**（表示已标准化，
  不要再标化一次），否则二次标准化会改变权重；
- **标准式 vs 修正式不是"谁更准"**，而是取值分布不同：标准式偏向 1 一端、
  区分度差；修正式把分布拉回中段。本案例两个都给了；
- **`obstacle_degree()` 只算二级指标障碍度**，一级（子系统级）要自己汇总；
- **障碍度是相对值，直接比大小即可**，不需要再行归一化（`scale = TRUE` 才做）。

## 踩过的坑

1. **`weight_entropy()$s` 已在 0–100 量纲**（本例子系统得分 5.09 ~ 85.16），
   不要重复乘 100（同案例 01）；
2. **`coupling_degree(data, w, id_cols=)` 的 `data` 必须是已归一化的子系统得分**，
   `id_cols` 指定不参与计算的 ID 列；
3. **不要凭直觉写"修正式的标准差更大"**——本案例实测标准式标准差 0.1955 >
   修正式 0.1906，与直觉相反。差异真正体现在**分布形状**（挤在 0.9 以上的比例），
   所以日志按实测数据陈述，不写想当然的结论。

## 实测结论（本案例数据）

- 子系统权重（熵权）：科技 **0.3899** / 经济 **0.2840** / 生态 **0.3261**；
- 标准式耦合度均值 **0.8982**，其中 **74%** 的样本挤在 0.9 以上；
  修正式均值 **0.6549**，0% 落在 0.9 以上 —— 这就是"区分度差"的量化证据；
- 末年协调等级：上海 / 北京 / 广东（良好协调），浙江（中级协调），江苏（初级协调），
  山东 / 福建（勉强协调），天津（濒临失调）；
- 障碍子系统：全样本中"科技"是主要瓶颈 61 次、"生态"19 次。
